# 04 — المصادقة، الصلاحيات، التدقيق، الإعدادات، ومعالج التهيئة

> **إلى الذكاء الاصطناعي المنفِّذ:** يغطي هذا الملف إدارة المستخدمين، الأدوار الثلاثة، سجل التدقيق، إعدادات النظام، معالج التهيئة الأولية (Setup Wizard)، وإقفال الفترات.

---

## 1. المصادقة والأدوار (Authentication & RBAC)

### 1.1 تسجيل الدخول (`/login`)
- شاشة دخول عربية بسيطة: `اسم المستخدم` + `كلمة المرور` + زر `تسجيل الدخول`.
- الجلسة تُحفظ في Cookie `HttpOnly` مشفر صالح لمدة 7 أيام.
- إذا لم يكن المستخدم مسجلاً الدخول، يُعاد توجيهه إلى `/login`.

### 1.2 مصفوفة الصلاحيات (`UserRole`)

| الصلاحية / الشاشة | `ADMIN` (المالك/المدير) | `ACCOUNTANT` (المحاسب) | `CASHIER` (البائع/الكاشير) |
|---|---|---|---|
| **المبيعات** (إنشاء وعرض وطباعة فاتورة) | ✅ | ✅ | ✅ |
| **تحصيل عميل** و**رد مبلغ لعميل** | ✅ | ✅ | ✅ |
| **عملاء السائقين** (تسجيل زيارة زائر) | ✅ | ✅ | ✅ |
| **صرف المخزون** (تستر / عينة) | ✅ | ✅ | ✅ |
| **إضافة عميل جديد أو سائق جديد** | ✅ | ✅ | ✅ |
| **المشتريات** و**سداد الموردين** | ✅ | ✅ | ❌ (لا يرى أسعار التكلفة للموردين) |
| **المرتجعات** (بيع وشراء) | ✅ | ✅ | ✅ (مرتجع بيع فقط) |
| **التصنيع ومواد التصنيع** | ✅ | ✅ | ❌ |
| **الحسابات والمدفوعات** (شركاء، تمويل، قروض، أصول، مصروفات) | ✅ | ✅ | ❌ (يرى فقط سندات العملاء وهدايا السائقين) |
| **التقارير المالية والأرباح** (`الرئيسية`، `الشركاء`) | ✅ | ✅ | ❌ (يرى لوحة كاشير مبسطة لمبيعات اليوم) |
| **إلغاء مستند معتمد (`VOID`)** | ✅ | ✅ (في الفترة المفتوحة) | ❌ |
| **الإعدادات وأرصدة البداية والمستخدمين وقفل الفترة** | ✅ | ❌ | ❌ |

> **قيد أمني:** يجب فحص الدور داخل كل `Server Action` و`API Route` عبر دالة `requireRole(['ADMIN', 'ACCOUNTANT'])` وليس بإخفاء الأزرار في الواجهة فقط.

## 2. سجل التدقيق والإلغاء الآمن (Audit Log & Voiding)

1. **ممنوع الحذف الفيزيائي (`DELETE`) لأي حركة مالية أو مخزنية** بعد حفظها (`PurchaseInvoice`, `SaleInvoice`, `CashTransaction`, `ReturnLine`, `StockIssue`, `ProductionBatch`, `DriverReferral`).
2. بدلاً من الحذف، يوجد زر **"إلغاء المستند (Void)"**:
   - يفتح نافذة تطلب `سبب الإلغاء` (إلزامي، 3 أحرف على الأقل).
   - يحول `status` إلى `VOID`، ويسجل `voidReason` و`voidedAt`، ويكتب سطراً في `AuditLog`.
   - **قاعدة تكامل عند الإلغاء:**
     - لا يمكن إلغاء **فاتورة بيع** أو **فاتورة شراء** إذا كان عليها **تحصيل/سداد/رد نقدي معتمد (`POSTED`)** أو **مرتجع معتمد (`POSTED`)**؛ يجب أولاً إلغاء الحركات المرتبطة بها أو تظهر رسالة: `"لا يمكن إلغاء الفاتورة لوجود تحصيلات أو مرتجعات مرتبطة بها؛ ألغِ الحركات المرتبطة أولاً"`.
     - عند إلغاء `DriverReferral`، إذا كان إلغاؤها يجعل إجمالي استحقاق السائق أقل مما استلمه فعلاً، يظهر تحذير واضح للمدير قبل التأكيد.
3. **شاشة سجل التدقيق (`/settings/audit`):**
   - تعرض جدولاً زمنياً بكل عمليات الإنشاء والتعديل والإلغاء مع اسم المستخدم، التاريخ والوقت، نوع السجل، كوده، والسبب.

## 3. الإعدادات وحالة التأسيس (`SystemSetting`)

تطابق ورقة `الإعدادات والتهيئة` والخلية `C7` في `الرئيسية والتقارير`:

### 3.1 الحقول القابلة للضبط في `/settings`
1. `storeName`: اسم المحل (يظهر في القائمة العلوية وفي ترويسة طباعة الفواتير).
2. `currencyCode` و`currencyLabel`: قائمة منسدلة (`روبية (IDR)`, `ريال سعودي (SAR)`, `درهم إماراتي (AED)`, `دولار أمريكي (USD)`).
3. `startYear`: سنة البداية الثابتة (افتراضياً `2026`). لا يُسمح بتغييرها بعد وجود حركات مسجلة.
4. `openingCash`: رصيد الخزينة عند بداية السجلات (`>= 0`).
5. `openingBank`: رصيد البنك عند بداية السجلات (`>= 0`).
6. `openingLoans`: قروض افتتاحية (`>= 0`).
7. `openingRetainedEarnings`: أرباح مرحلة افتتاحية.
8. `approveOpeningAssets`: مفتاح تبديل (`نعم / لا`) لاعتماد القيم المقدمة للأصول الافتتاحية.
9. `openingReviewed`: مفتاح تبديل (`نعم / لا`) لتأكيد مراجعة أرصدة البداية.
10. `allowNegativeStock`: مفتاح تبديل (`نعم / لا` — افتراضياً `لا` لمنع البيع أو الصرف فوق الرصيد المتاح).
11. `lockedThroughDate`: تاريخ إقفال الفترة (أي عملية تاريخها `<= lockedThroughDate` يُمنع إنشاؤها أو تعديلها أو إلغاؤها إلا بعد فك القفل من `ADMIN`).

### 3.2 معادلة "حالة التأسيس" (مطابقة للخلية `C7` في الرئيسية)
تُحسَب حالة التأسيس لعرض شريط الحالة في أعلى لوحة التحكم:
- الشروط الأربعة لاكتمال التأسيس:
  1. تحديد العملة (`currencyCode != ""`).
  2. تأكيد مراجعة الأرصدة (`openingReviewed == true`).
  3. حسم اعتماد الأصول الافتتاحية (`approveOpeningAssets == true` أو أن جميع الأصول قيمتها المقدمة = `0`).
  4. وجود سياسة هدايا سائقين واحدة على الأقل بقيمة محددة (`GiftPolicy.count >= 1`).
- إذا تحققت كلها: يظهر شريط أخضر `"تم تأكيد أرصدة البداية والتهيئة بالكامل"`.
- إذا نقص أي شرط: يظهر شريط تنبيه أصفر يحدد العناصر الناقصة بالاسم مع زر ينقل المستخدم مباشرة إلى خطوة الإكمال.

## 4. معالج التهيئة الأولية السريع (`/setup` — Setup Wizard)

ترجمةً للشرائح `2` و`4` و`6–12` من عرض التدريب (`ترتيب إدخال البيانات`)، يوفر النظام معالجاً من **6 خطوات متسلسلة** للمستخدم الجديد:

1. **الخطوة 1 — العملة وسنة البداية والنقد الافتتاحي:** اختيار العملة (`IDR`)، سنة البداية (`2026`)، رصيد الخزينة، ورصيد البنك.
2. **الخطوة 2 — الأصناف ومخزون أول المدة:** إضافة الأصناف أو استيرادها وإدخال `كمية أول المدة` و`قيمة أول المدة` لكل صنف، مع تنبيه: *"لا تُسجّل مخزون البداية مرة أخرى كفاتورة شراء"*.
3. **الخطوة 3 — الأسماء وديون أول المدة:** إدخال العملاء والموردين والسائقين والشركاء والممولين وأرصدة أول المدة إن وُجدت.
4. **الخطوة 4 — الأصول الثابتة الافتتاحية:** مراجعة الأصول الـ 13 المحفوظة (`170,386,000 IDR`) واختيار إما اعتمادها (`نعم`) أو تصفير غير المعتمد منها.
5. **الخطوة 5 — الشركاء ومطابقة حقوق ملكية البداية:** عرض `حقوق ملكية البداية` المحسوبة تلقائياً، وتوزيع `رأس مال أول المدة` ونسبة الربح على الشركاء حتى يصبح `فرق توزيع الافتتاح = 0`.
6. **الخطوة 6 — سياسة هدايا السائقين والاعتماد النهائي:** تحديد عدد العملاء لكل هدية (مثلاً `10`) وقيمة الهدية (مثلاً `100,000`)، ثم الضغط على زر **"تأكيد واعتماد أرصدة البداية"**.
