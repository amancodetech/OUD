# Oud ERP — ملف البداية (اقرأ هذا أولاً)

> **إلى الذكاء الاصطناعي المنفِّذ:** هذه المجلدات هي "العقد" الكامل للمشروع. لا تكتب أي كود قبل قراءة هذا الملف ثم الملفات `01` و`02` و`03` كاملة. نفّذ **مرحلة واحدة فقط** في كل مرة وفق ملف `18-roadmap-prompts.md`.

## 1. ما هو المشروع؟

تحويل نظام Excel اسمه `oud_system (7).xlsx` (نظام محل عود وعطور في إندونيسيا، العملة الافتراضية روبية IDR) إلى **تطبيق ويب ERP بسيط** باللغة العربية (RTL)، سهل الإدخال، يعمل على الكمبيوتر والتابلت.

النظام الحالي في Excel يحتوي على 18 ورقة: المبيعات، المشتريات، الحسابات والمدفوعات (الخزينة/البنك)، المرتجعات، صرف المخزون (تستر/عينات/تالف)، التصنيع ومواد التصنيع، الأصناف، الأسماء (عملاء/موردين/سائقين/شركاء/ممولين)، الشركاء، الأصول، عملاء السائقين وهداياهم وسياسة الهدايا، الإعدادات، وتقارير (الرئيسية، المخزون، المديونية).

ملف التدريب `oud_system_training_ar (1).pptx` يشرح طريقة العمل ويحتوي **مثالاً كاملاً بأرقام نهائية**، وقد حوّلناه إلى اختبار قبول إلزامي في `16-testing-golden-scenario.md`.

## 2. لماذا الويب أفضل من Excel هنا؟ (الأهداف)

| مشكلة في Excel | الحل في الويب |
|---|---|
| المستخدم يكتب المعرّفات يدويًا (S000001, C000001...) | توليد تلقائي لكل الأكواد |
| الفاتورة = عدة صفوف مكررة الرقم والتاريخ | فاتورة برأس + سطور في شاشة واحدة |
| أعمدة "تنبيه" تُظهر الأخطاء بعد الإدخال | منع الحفظ مع رسالة عربية واضحة قبل الحفظ |
| البيع النقدي يتطلب إدخالين (بيع + تحصيل) | حقل "المدفوع الآن" ينشئ التحصيل تلقائيًا |
| حد 3 سنوات (36 شهراً) | بلا حد زمني |
| لا صلاحيات ولا سجل تعديلات | مستخدمون وأدوار وسجل تدقيق |
| لا كشف حساب ولا كارت صنف ولا تحويل بين الخزينة والبنك | مضافة |
| ملف واحد قابل للتلف | قاعدة بيانات + نسخ احتياطي يومي |

**يجب أن تبقى نتائج الحسابات مطابقة لـ Excel** (التكلفة، الأرباح، المديونية، المخزون، الهدايا). أي اختلاف رقمي = خطأ.

## 4. قواعد إلزامية للذكاء الاصطناعي المنفِّذ

1. **لا تخترع.** لا تضف ميزة أو حقلاً أو جدولاً غير موجود في المواصفات. إذا احتجت شيئًا غير مذكور، توقف واسأل.
2. **لا تغيّر المعادلات.** كل معادلة في `11` و`12` و`13` و`14` منقولة من Excel. انسخها حرفيًا.
3. **مرحلة واحدة في كل مرة.** لا تبدأ المرحلة التالية قبل نجاح اختبارات المرحلة الحالية.
4. **المحرك المحاسبي دوال نقية** في `src/domain/` (بدون قاعدة بيانات وبدون React) ومغطى باختبارات Vitest.
5. **لا تستخدم `number` للمال أو الكميات** في الحسابات. استخدم `Decimal` (decimal.js / Prisma.Decimal). انظر `02`.
6. **كل نص يراه المستخدم بالعربية**، وكل أسماء الكود (متغيرات، جداول، دوال) بالإنجليزية كما في `03`.
7. **لا حذف فعلي للمستندات.** الإلغاء = `status = VOID` مع سبب. المستندات الملغاة تُستبعد من كل الحسابات.
8. **كل كتابة في قاعدة البيانات داخل `prisma.$transaction`** عندما تمس أكثر من جدول (مثل فاتورة + تحصيل فوري).
9. **التحقق في الخادم إلزامي** (zod + قواعد الأعمال في services) حتى لو تحققت الواجهة.
10. **عند الانتهاء من أي مرحلة** شغّل: `pnpm lint && pnpm typecheck && pnpm test` ويجب أن تنجح كلها، ثم اكتب ملخصًا بما أُنجز وما لم يُنجز.
11. إذا وجدت تعارضًا بين ملفين، فالأولوية: `16` (الاختبارات) ← `11/12/13` (المحركات) ← `01` ← بقية الملفات. واذكر التعارض في ملخصك.

## 6. خارج النطاق في الإصدار الأول (لا تنفّذه)

- الإهلاك المحاسبي للأصول (النظام يعرض "القيمة قبل الإهلاك" فقط كما في Excel).
- الضرائب (VAT/PPN).
- تعدد العملات في نفس النظام (عملة واحدة تُحدَّد في الإعدادات).
- تعدد الفروع/المستودعات.
- قيود اليومية المزدوجة (Journal entries) — الحسابات تُشتق مباشرة من المستندات كما في Excel.
- تطبيق جوال أصلي (الواجهة متجاوبة تكفي).
- دفع إلكتروني أو ربط بنكي.
