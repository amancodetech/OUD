# تقرير تنفيذ تحسين البيانات والكاش

التاريخ: 29 أكتوبر 2026. نُفذت الخطة في الكود بمساعدة Sol 6.1، ثم روجعت واختبرت على قاعدة PostgreSQL مؤقتة ومحاكي Workers ومتصفح Chrome معزول. لم تُنشر النسخة إلى حساب Cloudflare ولم تُطبّق الترحيلات الجديدة على قاعدة العمل.

## السلوك النهائي

- يحتفظ المتصفح بنتائج القراءة المشفرة طوال جلسة الدخول، بما فيها الصفحات والفلاتر التي زارها المستخدم. عند الرجوع تظهر النسخة المعروفة ويحدثها الخادم في الخلفية.
- يبقى الكاش بعد تحديث الصفحة، بعد التحقق من الجلسة أولًا. يُمسح عند الخروج أو انتهاء الجلسة أو تغير الصلاحيات، وتُقفل التبويبات الأخرى. المفتاح في الذاكرة فقط، وطلبات الحفظ لا تُخزن لإرسالها دون اتصال.
- الحفظ المالي مؤكد من الخادم، مع إيصالات لمنع التكرار وإصدارات لمنع الكتابة فوق تعديلات الآخرين. تعارض الإصدار يعيد 409؛ الإصدار المفقود يعيد 428.
- Workers يستخدم اتصال Prisma/PostgreSQL خاصًا بكل طلب، وHyperdrive دون تخزين نتائج الاستعلامات. الاستيراد والنسخ والاستعادة تنتقل إلى Queue وR2 خاصين عند التشغيل على Workers.
- جرى تخفيف استعلامات الاختيار، وتحويل الصفحات والتقارير الأساسية إلى إعادة عرض البيانات المحفوظة أثناء التحديث.

## دليل التحقق

| الفحص | النتيجة |
|---|---|
| مجموعة التكامل على قاعدة جديدة معزولة | 1604 اختبارات ناجحة في 26 ملفًا |
| اختبارات الكاش بعد إصلاح طلب الخروج | 18 اختبارًا ناجحًا، تشمل اختبارًا إضافيًا لصيغة الأوامر الفارغة |
| ترحيلات قاعدة البيانات | نجاح الإنشاء والترقية من المخططات السابقة في أداة التكامل |
| تشغيل Workers محليًا | نجاح الدخول، الطلبات المتزامنة، الإيصالات، تعارض الإصدار، Queue/R2 والتصدير الخاص والخروج |
| متصفح فعلي | بيانات مشفرة في IndexedDB؛ رجوع للوحة خلال 280ms مع حجب رد التقرير؛ نجاح إعادة التحميل من الكاش؛ حذف السجلات والخروج في تبويبين |
| TypeScript وESLint | ناجحان |
| npm audit | صفر ثغرات معلنة في الفحص المنفذ |
| بناء Cloudflare وdry-run | ناجحان دون نشر؛ إزالة ملفات البيئة المضمّنة وفحص الأسرار المعروفة |
| بناء Docker واستعلام Prisma من الصورة | ناجحان؛ أضيف ملف WASM اللازم للتشغيل |
| دور قاعدة التشغيل على قاعدة الاختبار | قراءة وتعديل الجداول متاحان؛ إنشاء المخطط وتعديل سجل الترحيلات غير متاحين |

قياس 280ms محلي مع حجب طلب التقرير لإثبات الكاش، وليس وعدًا بزمن استجابة Supabase أو Cloudflare. ملفات إثبات المتصفح محفوظة محليًا في `reports/cloudflare/` ولا تُنشر ضمن المصدر.

كشف اختبار المتصفح وأُصلح خلال التنفيذ: إخفاء البيانات المستعادة خلف علامة التحميل، ورفض Workers لطلب الخروج الفارغ مع انتقال الواجهة رغم الرفض. أصبحت الأوامر الفارغة ترسل JSON صريحًا، ولا ينتقل الخروج إلا بعد النجاح. كشف اختبار Docker نقص ملف محرك Prisma الديناميكي وأُصلح تضمينه.

## المتبقي قبل الإنتاج

اتبع [دليل النشر](CLOUDFLARE-DEPLOYMENT.md): تهيئة Hyperdrive وQueues وR2 والدومين والأسرار، تطبيق الترحيلات بحساب المالك مع نسخة قابلة للاستعادة، ثم اختبار staging والمطابقة المحاسبية وقياس الأداء من موقع الاستخدام. هذه خطوات تشغيل سحابي، ولا يثبتها البناء المحلي.

القراءة الأولى لكل صفحة أو فلتر غير مخزن تحتاج الشبكة. بعد إعادة تحميل المتصفح يلزم التحقق من الجلسة قبل فتح الكاش. تحديث أجهزة أخرى يُكتشف بفحص الإصدار كل 30 ثانية أثناء ظهور الصفحة، وليس بثًا لحظيًا. حصة التخزين يحددها المتصفح؛ عند تعذر التخزين يظهر تنبيه ويستمر العمل من الذاكرة.

أُعيد تشغيل الموقع القديم على المنفذ 3000 بطلب المستخدم؛ إعادة التشغيل وحدها لا تفعّل هذه التعديلات. لا ترفع ملفات البيئة أو تاريخ Git القديم إلى GitHub؛ استخدم `npm run release:source` لنسخة مصدر نظيفة.
