# تشغيل وصيانة OUD بعد الإصلاح

يلزم Node.js 22.12 أو أحدث ضمن إصدار 22، وPostgreSQL 17. اختُبر الإصلاح على 17.11. لا تشغّل سكربتات التهيئة أو الاختبارات على قاعدة العمل.

## الاختبارات

- `npm test` يشغّل اختبارات المجال والحدود دون اتصال بقاعدة العمل.
- `npm run test:integration` ينشئ حاوية PostgreSQL وقاعدة باسم `oud_test_<run>`، ويتحقق من اسمها، ويهيئها ويختبرها ثم يزيلها.
- `OUD_KEEP_TEST_DB=1` يحتفظ بالقاعدة الناجحة ويكتب إعدادها في ملف خاص داخل `/tmp` لأغراض الفحص. لا تستخدم ملف `.env` الخاص بالعمل للاختبارات.
- `scripts/verify-migrations.mjs` يختبر ترحيل مخطط قديم داخل قاعدة اختبار منفصلة، ويثبت بقاء سجل مورد ورصيده.

## إعداد جديد

1. انسخ `.env.example` وحدد `DATABASE_URL` و`SESSION_SECRET` عشوائيًا طويلًا، و`APP_URL` بالأصل الذي سيستخدمه المتصفح، مثل `https://oud.example.com`. لا تعرض الأسرار في السجلات أو تلتزم بها في Git.
2. نفّذ `npm ci` و`npx prisma generate` و`npm run db:migrate` على قاعدة التثبيت الجديدة المحددة صراحةً.
3. أنشئ المدير الأول باستخدام `scripts/create-admin.mjs` مع `SETUP_DATABASE_URL` و`INITIAL_ADMIN_PASSWORD` من بيئة خاصة. الأداة ترفض وجود حسابات سابقة. لا توجد كلمة مرور إنتاج افتراضية.
4. أكمل البيانات الأساسية من الشاشات، أو استخدم `prisma/seed.ts` مع `SEED_DATABASE_URL` و`INITIAL_ADMIN_PASSWORD` على قاعدة فارغة فقط. لا تستخدم سكربتات التجارب لتهيئة العمل.
5. نفّذ `npm run build` ثم `npm start`. أمر التشغيل يتحقق من الأسرار والعنوان. تشغيل standalone داخل Docker يستخدم `scripts/server-entry.mjs`. الخط محلي ولا يتطلب الاتصال بـGoogle Fonts.

## ترحيل قاعدة موجودة

احتفظ بنسخة `pg_dump` كاملة واختبر استعادتها. ملف `prisma/baseline/schema.prisma` يثبت مخطط النسخة القديمة الملتزم بها في Git، و`prisma/baseline/pre-remediation.prisma` يثبت المخطط الوسيط الذي أضيفت إليه الترجمة والصلاحيات. قارن قاعدة التثبيت بأحد هذين المخططين قبل تسجيل baseline. لا تنفّذ SQL إنشاء baseline على قاعدة تحتوي الجداول.

الترحيل التاريخي `202610260001_baseline` محفوظ دون تعديل لأن تثبيتات قائمة سجلته بالفعل. على قاعدة تطابق المخطط القديم، يُسجّل كمطبّق ثم تُنفّذ الترحيلات الإضافية؛ `202610270001_legacy_columns` ينشئ كل الأعمدة التي لم تكن موجودة في النسخة القديمة. استخدام `IF NOT EXISTS` يحافظ على الترجمات والصلاحيات ومبالغ الفواتير الافتتاحية الموجودة في التثبيتات الوسيطة. رصيد `openingBalance` القديم يبقى كما هو ولا تُستنتج منه فواتير أو دفعات تاريخية.

بعد فحص الفرق على نسخة مؤقتة ومراجعة البيانات، حدّد `DATABASE_URL` صراحةً لأوامر Prisma:

```sh
npx prisma migrate resolve --applied 202610260001_baseline
npx prisma migrate deploy
```

إذا كان baseline مسجلًا بالفعل، نفّذ `migrate deploy` فقط. سكربت `activate-remediation.mjs --plan` يتعرف على المخطط القديم والوسيط والسابق لإضافة معرف الجلسة والحالي، ويرفض أي اختلاف غير معروف. خيار `--apply` يحفظ نسخة كاملة ويقارن البيانات قبل الترقية وبعدها، كما يدوّر سر الجلسات؛ لا تستخدمه لمجرد إعادة تشغيل التطبيق.

الترحيل `202610260002_integrity` يضيف `sessionVersion` ورابط سند المرتجع التلقائي وجدولي مولّد الأكواد ومحاولات الدخول. الترحيل `202610270002_session_generation` يضيف معرف جلسة عشوائيًا لكل مستخدم. لا تغيّر هذه الترحيلات الأرصدة. الجلسات القديمة تتوقف ويجب إعادة الدخول. روابط المرتجعات القديمة لا تُستنتج آليًا من النصوص؛ راجع الحركات القديمة غير المرتبطة قبل إلغائها.

اختبار `npm run test:integration` يتحقق تلقائيًا من أربعة مسارات: المخطط القديم الفعلي، والمخطط الوسيط، والإصدار السابق لمعرف الجلسة، وقاعدة جديدة. يفحص تطابق المخطط النهائي، وقراءات Prisma، وبقاء الأرصدة والترجمات والصلاحيات، وإعادة الترحيل دون تغيير إضافي.

## النسخ والاستعادة

JSON بإصدار 2 نسخة كاملة قابلة لاستبدال البيانات، وتشمل المستخدمين وكلمات المرور المجزأة والتدقيق. الملف غير مشفر؛ احفظه في تخزين خاص. Excel تصدير للمراجعة وليس بديلًا عن النسخة الكاملة. الاستعادة من الواجهة تتطلب مديرًا وتأكيد الاستبدال وسببًا، وتتم بمعاملة واحدة وتبطل جميع الجلسات بمعرفات عشوائية جديدة لا تؤخذ من النسخة. إعادة الملف نفسه أو ملف أقدم لا تعيد صلاحية أي جلسة سابقة؛ تُقبل نسخة الإصدار 2 السابقة لإضافة المعرف أيضًا. النسخ التطبيقية القديمة ذات الصيغة غير الكاملة تُرفض بدل ادعاء استعادتها كاملة.

للنسخة المستقلة من PostgreSQL، حدد `BACKUP_DATABASE_URL` و`BACKUP_DIR` و`BACKUP_RETENTION_DAYS` ثم شغّل `npm run backup`. الأداة تستخدم `pg_dump` بصيغة custom وتحفظ SHA-256 وتزيل ملفاتها القديمة فقط بعد فترة الاحتفاظ. يلزم `pg_dump` بإصدار يوافق PostgreSQL 17 أو أحدث. لم تُفعّل جدولة على قاعدة العمل أثناء الإصلاح.

مثال cron بعد إعداده ومراجعته على الخادم:

```cron
0 2 * * * cd /srv/oud && /usr/bin/node --env-file=.env scripts/backup.mjs >> /var/log/oud-backup.log 2>&1
```

اختبر الاستعادة على قاعدة فارغة مؤقتة باستخدام `pg_restore --single-transaction`، وقارن السجلات والأرصدة والعلاقات. احتفظ بنسخة خارج جهاز التشغيل أيضًا.

## حدود التشغيل

تُسلسل عمليات الكتابة بقفل ledger واحد لحماية الفحص والترقيم والتدقيق. قراءات المحركات تستخدم snapshot متسقًا. مع نمو البيانات ينبغي قياس مدة المعاملات وتضييق نطاقات التحميل وإضافة صفحات للقوائم. لا تحسب الإجماليات المالية من صفحة واحدة، ولا تستخدم cache قديمًا للأرصدة.

طلبات الحفظ التي تحمل `Idempotency-Key` تعيد نتيجة الطلب الأول وتمنع تكراره أو تغيير محتواه تحت المفتاح نفسه. API يفرض الصلاحيات بغض النظر عن القائمة الجانبية. الطلبات ذات بيانات JSON تتطلب `application/json`؛ الاستيراد وحده يقبل `multipart/form-data`. إلغاء السندات يتحقق من نوع المستند المخزن داخل معاملة الإلغاء. مسار `/api/returns/source-invoices` يوفر بيانات محدودة لمشغلي المرتجعات، و`/api/settings/branding` يعرض اسم المتجر فقط للمستخدم المسجل. مدة حد محاولات الدخول 15 دقيقة ويشترك فيه جميع عمليات الخادم.
