## الضوابط

- يبقى الكاش المشفر طوال جلسة الدخول، ويُمحى عند الخروج أو انتهاء الجلسة أو إبطالها. المصدر المعتمد للحفظ هو الخادم.
- لا تغيير لقاعدة البيانات أو الحسابات أو الأرصدة ضمن إصلاح الكاش، ولا نقل تلقائي بين مشروعات Supabase.
- مشروع الاتصال الحالي `eiesummskggttulzujsw` مختلف عن المشروع الأصلي `ebkgaxhauufptfipddyv`؛ طُلب توضيح اعتماد المشروع. هذا مستقل عن الإصلاحات التقنية.
- الاحتفاظ ببيانات مفتاح معين لا يعني ضمان زمن صفر لأول زيارة أو عند التحقق من الجلسة. يُفصل اختبار الكاش عن زمن شبكة Supabase.
- الاختبارات تستخدم بيانات وهمية أو قاعدة مؤقتة. لا إجراء اختبارات كتابة على قاعدة المتجر.

## ترتيب التحقق

1. اختبارات انحدار محددة لكل إصلاح بدل تكرار اختبارات حمل واسعة.
2. سيناريوهات متصفح تستخدم مكونات التطبيق الفعلية: الحفظ أثناء طلب معلق، انتقال الفلاتر، فشل التحديث، التبويبان، مفاتيح التحميل المسبق، صلاحيات مستخدم محدود، والخروج.
3. TypeScript وESLint وبناء الإنتاج بعد استقرار التعديلات.
4. مراجعة Astra مستقلة للكود ونتائج الاختبار. يُوثق أي قيد متبقٍ بصراحة.
